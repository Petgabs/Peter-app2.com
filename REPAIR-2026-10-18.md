# Repair report — 2026-10-18

Scope: published Year 11 Preliminary Student Report Studio
(`https://petgabs.github.io/Peter-app2.com/`), its Supabase school cloud, CAL
learner-profile import, and PDF/Help accuracy. **No production student records,
school settings or live cloud policies were changed by this repair.** All data
tests used synthetic records in jsdom. Any password shared during earlier
troubleshooting should be rotated; none is reproduced here.

## (a) Root-cause explanation

1. **42P17 / HTTP 500 on `profiles` and `app_config`.** The policy
   `"admin manage profiles"` on `public.profiles` (and `"admins write app
   config"` on `public.app_config`) contained
   `EXISTS (SELECT 1 FROM public.profiles …)`. PostgreSQL evaluates policies on
   `profiles` while reading `profiles`, so the subquery re-enters RLS on the
   same relation and the server aborts with SQLSTATE **42P17** ("infinite
   recursion detected in policy"). Every profile lookup therefore failed.
2. **Silent role degradation.** `sbFetchProfile()` ignored non-OK responses and
   left the session at its default `teacher` role, while `cloudReason()`
   returned a healthy state whenever a session existed — hence "Teacher
   session" plus a green "Cloud: school" badge, and an extra admin-login wall
   for Cloud sync.
3. **CAL import rejection.** `cleanReport()` validated learner-profile values
   against the four frequency descriptors only, so source data carrying CAL
   profile codes A–D was rejected, even though rendering expects descriptors
   (`DOTS[RATING[…]]`).
4. **Help inaccuracy.** Help implied a downloaded `index.html` alone contains
   the PDF renderer; since PR #10 the renderer lives in `vendor/pdf-libs.js`
   and is lazy-loaded.
5. **Bonus defect found during repair:** the earlier `scope="col"` change had
   corrupted 13 `<thead>` elements into `<th scope="col"ead>`; repaired.

## (b) Source changes (this PR)

- `supabase-migration-2026-10-18-fix-rls-recursion.sql` — **reviewed, not yet
  applied to the live project.** Adds `public.is_admin()` / `public.is_staff()`
  (`SECURITY DEFINER`, `set search_path = public`, execute revoked from
  `PUBLIC`/`anon`, granted to `authenticated` only) and rebuilds the
  `profiles`, `report_files` and `app_config` policies on top of them. RLS
  stays enabled everywhere; no service-role key is introduced; anonymous users
  get no policy at all. `...rollback.sql` restores the previous policy set
  (with a warning that it reintroduces 42P17). `supabase-setup.sql` now
  contains the same fixed policy set for fresh installs.
- `index.html`
  - `sbFetchProfile()` records `sbProfileError` on HTTP failure, empty profile
    or network error; `cloudReason()` then reports an **error** state (badge
    "Cloud: error", never "school"), sign-in surfaces the message, privileged
    actions stay locked because the role remains teacher-level, and session
    restore (`bootCloud`) fails closed the same way.
  - CAL: for the subject whose code is `CAL` only, imported learner-profile
    codes `A/B/C/D` (any case, surrounding whitespace ignored) are normalised
    to `Consistently/Often/Occasionally/Rarely` **before** validation in
    `cleanReport()`, and `getReport()` applies the same normalisation for
    display, so both the individual CAL profile table and the course-by-course
    summary render ●●●● / ●●●○ / ●●○○ / ●○○○. Blank stays blank; anything else
    is rejected with an error that names the CAL conversion. Academic A–E
    grades, criterion grades, comments and identity fields are untouched, and
    other subjects' values are never reinterpreted.
  - Full-backup import now shows an explicit **COHORT WARNING** and requires a
    second confirmation before replacing a workspace whose academic year
    differs (a recovery snapshot is still taken first).
  - `<thead>` corruption repaired; Help (English + Simplified Chinese note)
    now documents the real offline package: `index.html` + `assets/` +
    `vendor/pdf-libs.js` + `sw.js`, and that one online PDF download caches
    the renderer.
- `tests/smoke.mjs` — mock Supabase can now return the real 42P17 payload;
  new section 7 covers role-failure behaviour, CAL mapping (all four codes,
  whitespace/case, invalid code, mixed subjects, full-preview dots), cohort
  guard, migration artefacts and Help accuracy.

## (d) Staged deployment / backup / rollback checklist

1. Coordinator exports a full backup from the app (Admin → Data transfer) and,
   in Supabase, copies `profiles`, `app_config` and `report_files` contents to a
   private location. Record row counts.
2. On a **staging** Supabase project (or after hours on production with the
   backup above), run `supabase-migration-2026-10-18-fix-rls-recursion.sql` in
   the SQL editor.
3. Verify with test accounts (no real student edits): admin profile GET → 200
   `role=admin`; teacher profile GET → 200 `role=teacher`; teacher
   `app_config` GET → 200, POST → 401/403; anon `report_files` GET → 401/403
   and no rows; create → save → refresh → second-browser sync → delete a
   **fictional** student; check tombstones propagate.
4. Only then reload the published site (this PR's merge deploys the app code;
   Pages build must show the new commit) and repeat the sign-in checks live.
5. Rollback if anything regresses: run
   `supabase-migration-2026-10-18-fix-rls-recursion.rollback.sql` (accepts the
   42P17 outage returning) or re-apply the migration after fixing the cause;
   app code rolls back by reverting this PR's merge commit.
6. **2026 cohort:** do not relabel the existing 2027 workspace. Whether a
   separate authorised 2026 dataset exists could not be determined from the
   sandbox (no live database access, and no student data was inspected). If
   2026 reports must be loaded: export the current cloud data first, prepare a
   separately scoped import file, dry-run it in staging with counts and
   identity checks, verify one permissioned anonymised sample against the
   approved 2026 edition, and only import after written school approval.
   Student data must never be committed to this public repository.

## Addendum — second pass (same day)

- **Least-privilege tightening:** the migration's `profiles` read policy now
  allows a signed-in user to read **only their own row** (`id = auth.uid()`),
  which is all the app ever requests. Admin writes still go through
  `is_admin()`; staff checks for `report_files`/`app_config` still go through
  `is_staff()`. Anon has no policy on any of the three tables. The
  `app_config` registry remains readable by signed-in staff only (it carries
  the shared repository token by the school's earlier design decision); it is
  not exposed to anonymous/public callers.
- **First-login PDF race (fixed):** `bootSync()` could call `render()` when
  the initial pull landed, and `render()` leaves preview mode — hiding a
  preview a teacher had just opened (and breaking an in-flight download).
  The initial pull/push is now a single cached promise
  (`initialSyncPromise`, reset on sign-out/idle lock); `bootSync()` and the
  background `autoRefresh()` never re-render while a preview is open, and
  `downloadCurrentPDF()` awaits the initial sync before touching the stage.
  Regression test: with the mock cloud artificially slowed, a preview opened
  immediately after sign-in survives the sync completing, and already-stored
  raw CAL letters then render as descriptors with dots.
- **Status of the live database:** unchanged by this pass. The migration in
  this repository has still **not** been applied to the production Supabase
  project, so `profiles`/`app_config` will keep returning 42P17/500 until
  the school runs it following section (d). That is the single blocking
  item; everything else in this addendum is app-side and deploys with the
  site.

## Addendum — fatal-banner escalation fixed

The profile-verification failure (HTTP 500 from the still-unmigrated live
database) was being passed to `showFatalError()` on session restore, so a
handled, teacher-level degradation appeared as a red "Something went wrong
in the app" crash banner. Fixed: session restore and the fatal-error
handler itself now treat that condition as a warning toast only, the
profile lookup retries once on a 5xx, and the message notes the database
policy fix is pending. Regression tests cover both fresh sign-in and
reload-with-saved-session against a mock 42P17. **The underlying HTTP 500
will persist until the school applies
`supabase-migration-2026-10-18-fix-rls-recursion.sql`** — no app change can
repair a database policy from the browser.
